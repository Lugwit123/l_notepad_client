# L Notepad 更新日志

## Unreleased

### 新增功能
- 📐 **行距收紧**（更紧凑）：
  - 笔记树：单行项（外部 / IPC 文件、搜索命中、服务器日志）行高 **32 → 20px** —— `_NoteTreeItemDelegate.sizeHint` 原来无论几行都返回 32px，单行项下方白空 12px；现按字体实测行高算（12px 字体 = 16px/行 + 4px 内边距）；「文件名 + 日期」两行项维持 32px（16px/行已是字体下限）。同时 `paint` 的竖直居中不再固定下偏 2px（两行项此前会往下溢出 2px 压到下一行）
  - 剪贴板列表（主面板 + Win+V 小窗）：文件行高 **26 → 20px**（`ClipboardItemDelegate._FILE_ROW_H`，图标 14px + 上下各 3px），列表 `setSpacing(2)` → **1px**；文字行 16px（字体下限）、图片行 56px（缩略图决定）不动。小窗高度按同一批常量推导，无需另改
- 🧹 剪贴板历史的**右键菜单统一**：Win+V 小窗与主面板列表共用同一份构建代码（`populate_clipboard_context_menu`），条目、顺序、文案完全一致——收藏/取消收藏、查看/编辑（仅收藏项）、按类型的复制类操作（复制文本 / 复制图片 + 另存图片为… / 复制文件 + 打开所在文件夹）、**使用此条**、删除此条、清除全部历史
  - 小窗补上此前只有主面板才有的复制类操作；主面板补上「使用此条」（等价于原来的双击 = 恢复系统剪贴板 + 粘贴回调用程序）
  - 小窗的「查看/编辑」「清除全部历史」「🗑 清除」改为直接调用主面板同一实现，不再各写一份（清空统一走带确认框、只清未收藏项的那条路径）
- 📋 左侧「※ 置顶/收藏」按钮换成 **「从剪切板打开文件」**：剪贴板里是文件路径时一键打开（首行非空内容，自动去掉包裹引号、展开 `%VAR%` 与 `~`），等价于在「打开文件」里选中该文件；路径非法只在状态栏提示，不弹窗。按钮不再随 AI/日志/外部文件模式禁用。收藏改走条目 ★ 星标与右键「收藏并置顶」，功能不受影响
- ⭐ 剪贴板历史新增**收藏（星标）**：条目右侧显示星标，点星标或右键「收藏此条」即可收藏。收藏项**恒置顶**，与主界面笔记的 ★ 收藏同一套星标绘制/热区交互——逻辑收敛到新模块 `star_favorite.py`，`_NoteTreeItemDelegate` 与剪贴板 delegate 共用
  - 收藏项**受保护**：「清除全部」（面板菜单与 Win+V 弹窗）只清未收藏项并在确认框标明「已收藏的 N 条会保留」；单条删除需先取消收藏；超出条数上限时只丢最旧的未收藏项，收藏永不因超限被丢
  - 主窗口「剪贴板历史」与 Win+V 弹窗共用同一份收藏态（同走单例 `ClipboardHistoryStore`），两处都能打星、都按「收藏在前」排序
  - 重新复制同一条内容不会丢掉已有收藏（`upsert_top` 合并时保留原 `favorite` 标记）
  - **「查看/编辑」只对收藏条目开放**：主窗口剪贴板列表右键菜单补齐该入口（此前只有 Win+V 弹窗有），但非收藏条目的右键菜单里不出现它；Win+V 弹窗原有的 Ctrl+双击编辑窗口同样只对收藏条目生效（非收藏走普通双击 = 粘贴回调用程序）
  - 编辑保存改为**按去重键定位**而非行号：对话框打开期间若发生新复制或收藏置顶（列表重排），保存仍命中同一条目、不会改错；`update_item_at` 一律沿用该行现有收藏标记，改文字不会把收藏弄丢
  - 收藏标记随历史落盘（`clipboard_history.json` 的 `favorite` 字段），取消星标即恢复为普通历史
- 👁️ 版本对比新增 **「源码 / 预览」双模式**：工具条可切换，默认仍是源码态（现行为逐字不变），切到「预览」后**改动块也照常渲染 Markdown，差异按行标进渲染结果**
  - 行级差异的落地方式：渲染输出本身按 `<br>` 断行（段落 hard_wrap、代码块高亮都是），逐行给行内内容套一层底色 → 渲染结构不变，段落 / 标题 / 代码块内哪一行变了都直接看得见（代码块保住了代码盒与语法配色）
  - 结构性块（列表 / 表格 / 引用等渲染后行与源码不再一一对应的块）**退回整块标色**——宁可粗一点，也不为逐行着色破坏渲染结构
  - 改动块内未变的行用更淡的 context 底色区分；缺内容的一侧按**对侧行数**补空行，避免左右高度错位
  - **字符级差异不在预览模式做**：渲染后 HTML 里字符偏移已不存在，只能在 markdown 源码层注入 `<span>`，而源码层注入会拆断强调标记 / 行内代码 / 表格列。字符级精度由源码模式提供，两个模式各负责一种精度
  - 预览模式：隐藏行号、差异导航按块槽位、两栏滚动**按比例**联动（两侧块高不再逐行相等）
  - 统计始终按行级口径，不随模式变化；预览下额外提示「改动块按行标出差异（列表/表格整块标色）；统计仍按行」
  - 非 Markdown 内容（`.log` / `.py` / 纯文本）不出现切换控件
  - 分块数超过 5000 时**拒绝进入预览并给出可见原因**（不静默降级成「按钮没反应」）；实测 600 块 / 414KB 渲染约 0.3s
  - 预览里相对路径图片仍不解析（库内无 `setBaseUrl` / `loadResource`，属既有限制），降级为占位、不报错
  - `l_qt_wgt_lib` 修一个**只读契约漏洞**：Markdown 预览层（`_MarkdownLivePreview`）自行实现了「渲染态直接编辑」，其按键 / 粘贴 / 拖放 / 输入法四条入口绕过了 `QTextEdit` 的只读态——宿主设了只读仍能改到正文。四条入口现补齐只读闸门（可编辑场景逐字不变）
  - 新文件 `openspec/changes/add-version-diff-preview-mode/`（proposal + design + 2 份 spec + tasks）
- ⚓ Markdown 预览支持**文档内跳转**：`[说明 ↓](#标题-slug)` 点击即滚到对应标题（GitHub 风格 slug，中文/标点与 GitHub 一致，如 `#d1--d2-活例getformfields接口可用但对参数极敏感`）；激活块源码态标题同样能匹配，找不到锚点不误动
- ⚡ Markdown 预览**输入性能**大幅提升：渲染态打字/退格不再整篇重建文档，只替换内容变化的那一块（1501 块 / 168KB 实测单键 **653ms → 6.3ms**）；另加逐块渲染缓存，重复块不再重复渲染
- 🔀 版本对比（并排 diff）：版本下拉框右侧新增「⇄ 差异」下拉框 ×2 + 「对比」按钮，默认 = **最新 vs 上一版**，点开后在双栏对话框里并排看改动
  - 行背景标色：删除红（左栏）、新增绿（右栏）、修改黄（两栏）；顶部显示 `新增 x 行 / 删除 y 行 / 修改 z 行`

  - 对比栏一律用**源码态**（`.md` 走 `markdown` 源码高亮而非预览），保证行号与源码 1:1 对齐
  - 版本数不足两个时按钮自动禁用；超长内容（> 20000 行）只对比前 20000 行并提示
  - 新文件 `version_diff_dialog.py`（`build_side_by_side` / `diff_stats` 纯函数，可单测）；设计见 `doc/版本对比与reload版本生成_设计.md`
- 🖱️ 滚动条加粗可抓（`style.qss`，全应用生效）：条身 10px → **12px**，手柄（滑块）设 **最小长度 40px**，长笔记内容下不再被压成几像素抓不住；手柄配色加深并补 hover/pressed 反馈

### 问题修复
- 💥 剪贴板条目**取消收藏**（点灭星标 / 右键取消）让客户端**当场崩溃**（无提示、无 Python 异常，只在 `l_notepad/crash_*.log` 留下 `access violation`）：
  - 根因：`clipboard_store._move_to_group_top` 把落点行号直接当 Qt 的 `destinationChild` 传给 `beginMoveRows`。同 parent **往下移**时 Qt 只接受 `落点 + 1`（传落点会落进非法区间 `[row, row + 1]`，`beginMoveRows` 返回 `False`），而代码不看返回值照样 `endMoveRows()` → 模型信号不成对、视图/代理行映射错位，访问违例（`crash_20260927.log` 崩在 `_move_to_group_top` 的 `endMoveRows`）。收藏是**上移**（dest < row），恰好合法，所以此前只有取消收藏会崩
  - 修复：下移时传 `target + 1`（上移保持原样），收藏置顶与取消收藏后的落点都对得上
  - 新增回归测试 `test_clipboard_favorite_toggle.py`：收藏/取消收藏反复切换（含「倒数第二个收藏项」等边界）不崩、条目不丢不重、过滤代理行序与源模型一致
- 🐛 Win+V 弹窗里**右键「使用此条」第一次只往调用程序输入框里打出个 `v`**（第二次才粘贴条目）：
  - 根因：粘贴是在 `QMenu.exec()` 的嵌套事件循环里做的——此刻菜单还抓着键盘，注入的 `Ctrl+V` 被拆散：Ctrl 被菜单/正在关闭的弹层吃掉、V 落到前台程序，于是调用程序只收到一个**裸 V**（被打成 `v`）；菜单彻底关掉后第二次自然就好
  - 修复：右键菜单只记「要用哪一条」，真正粘贴等 `menu.exec()` 返回、键盘抓取释放后再做
  - 同时把「固定等 80ms 就注入」换成**就绪轮询**（`paste_to_window_when_ready`）：轮询到「没有 Qt 弹层抓键盘」且「前台就是调用窗口（按 `GA_ROOT` 比对）」才发键，最多等 1s 再尽力而为；注入时打印 `fg / caller_root / 弹层抓键盘 / 等待` 便于排查
  - 主界面剪贴板列表的「双击粘贴回调用程序」是同一套盲等逻辑，一并换成就绪轮询
- 📐 剪贴板列表的**行矩形比可见 viewport 宽**（滚动条出现前就完成布局、之后不重排，`visualRect().right()` 会落到滚动条底下十几像素）→ 右对齐的收藏星标被压到滚动条边上、右侧留白形同虚设，而且**时有时无**（取决于布局发生在滚动条占位之前还是之后，重启后常复现）。现在绘制与点击热区统一按可见 viewport 裁剪（`star_favorite.visible_row_rect`），星标右缘留白 12px 稳定生效，热区也不再和滚动条重叠
- 💥 剪贴板历史**重启后被清空**（`clipboard_history.json` 被写成 `[]`，图片缓存却还在）：
  - 根因：`flush()` / `shutdown()` 会**无条件**把内存模型写盘，而历史是启动时异步加载的。只要进程在「加载事件被处理」之前退出（快速退出 / 崩溃 / 并行实例），模型还是空的，退出落盘就把磁盘上完整的历史覆盖成 `[]`；同理，历史文件**读取或解析失败**时旧代码按「空历史」处理，之后任何一次落盘都会把文件抹掉
  - 修复：新增「已成功加载」闸门 `_history_ready`——**未确认加载完成一律不写盘**；`_read_history` 区分「文件不存在（可信的空历史）」与「读取/解析失败（内容未知）」，失败时保留磁盘原文件、绝不覆盖；`cleanup_orphan_images` 在历史未加载时不再按不完整模型删图片；加载期间若已并入新条目则补一次落盘
  - 日志会打印「剪贴板历史未加载完成，暂不落盘（避免覆盖磁盘上的完整历史）」，便于排查
- 🧯 剪贴板历史**多实例互相覆盖**（同一份 `clipboard_history.json` 被两个客户端实例交替覆写）：
  - 落盘改为「跨进程锁 + 重读磁盘按去重键合并」：先对 `<history>.json.lock` 加 `msvcrt` 字节锁，再与磁盘内容取并集（内存条目原样保留，磁盘独有条目补进来，跳过本次已删的键），最后临时文件原子替换 —— 谁先退出都不会把对方的数据抹掉
  - 本进程显式删掉 / 清空 / **编辑改名**的键记入墓碑（改名等同作废旧 key），合并时不再从磁盘把它们捡回来，避免"删了又回来"
  - 上次写盘后文件指纹未变说明盘上就是自己刚写的，直接用上次 payload 参与合并，不重读整份 JSON
- 🚪 `l_notepad_client` 补齐 `.soloignore` 旧实例接管（`local_main._solo_takeover_if_peer`）：托盘启动项早已是 `wuwor l_notepad_client .soloignore -- l_notepad_client`，但本包一直没实现接管 → 重复点击会起第二个实例（也是上一条数据丢失的来源）。现在启动时按 wuwo 注入的 `L_SOLO_PEER_*` 清掉旧实例（`taskkill /F /T`；复核 `L_SOLO_PEER_CMDLINE` 确含本包，并排除自身与父进程，避免误杀把本次启动一起带走），读完**立刻摘掉 `L_SOLO_*` 环境变量**，防止自重启的子进程把刚起好的实例当旧实例再杀一次；清不掉时不退出（纯 GUI、无端口冲突，且存储层已能合并），只打告警
- 🔄 外部文件被外部修改后点「重载」**不生成新版本**：重载只刷新了编辑器与磁盘快照，未写入版本库，导致磁盘上的新内容永远进不了版本历史（对比时看不到这次改动）
  - 根因：版本库写入只挂在「打开文件」(`_set_external_file_editor`) 与三个保存路径上，`_reload_local_file_from_disk` 漏写
  - 修复：重载成功后补 `_record_version(kind, ref, title, text)`（`text` = 刚从磁盘读出的全文，避免 markdown 预览态取到非权威内容），位置在 `_record_loaded_local_file` 之后、`_sync_version_combo_on_open` 之前，版本下拉随即显示新版本
  - 内容未变时 `history_store.add_version` 自动去重，重复点重载不会刷出版本
- 🔄 外部修改弹窗后「笔记查看组件没更新」：
  - 根因：markdown 预览层（`_MarkdownLivePreview`）持有自己的源码副本，重载只写了隐藏的正文文档；且预览态 `toPlainText()` 读的是预览层 → 界面不更新，连后续 Ctrl+S 也会存回旧内容
  - 修复：`code_editor.apply_text_with_cache` 在预览态写入后显式重渲染预览层（保留滚动位置）
  - `_reload_local_file_from_disk` 增加「可见文本 == 磁盘内容」校验，不一致就强制刷新（预览态走 `show_markdown_preview`，源码态走 `setPlainText`），并打印 `[本地文件监控] 强制刷新编辑区`
- 🔄 本地文件被外部修改后无提示（笔记 / 外部文件）：
  - 根因一：`ui.py` 的 `MainWindow` 是 `L_FramelessMainWindow` 外壳的**内容子控件**，Qt 的 `WindowActivate` 只发给顶层窗口 → `changeEvent` 里的检查永不触发。改为在顶层窗口 `self.window()` 上 `installEventFilter` 过滤 `WindowActivate`/`ActivationChange`
  - 根因二：原先只在窗口重新激活的瞬间检查一次，且只对 `.log` 文件生效。新增 `QFileSystemWatcher`（文件 + 父目录）+ 1.5s `QTimer` 轮询兜底，窗口在前台时实时发现外部写盘
  - 编辑器有未保存修改（dirty）时不再静默跳过，改为明确提示「重载会丢弃你当前未保存的修改」
  - 快照比对由单一 mtime 扩展为 (mtime, size)；文件被外部删除时给出状态提示而非弹重载框
  - 新增 `[本地文件监控]` 诊断日志（记录快照 / 检测到外部修改 / 提示结果）
- 🔄 本地文件被外部修改后回到前台无提示：原先只对 `.log` 文件做变更检测，笔记与外部文件完全不检测
  - 检测范围扩展为「当前编辑的本地文件」（笔记 / 外部文件 / IPC 文件）
